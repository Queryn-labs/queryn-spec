# queryn-spec

Открытая исполняемая спецификация Queryn. Текущий формат проекта — `0.2`. `0.1` остаётся читаемым и мигрируется только явно.
Каноническая [страница документации](https://github.com/Queryn-labs/queryn-docs) содержит продуктовые и архитектурные пояснения к этим контрактам.

## Статус

Формат проекта `0.2` является текущим контрактом Queryn. Формат `0.1`
остаётся читаемым и переводится в `0.2` только явной миграцией.

## Stack

- JSON Schema Draft 2020-12
- Node.js-скрипты в формате ESM
- npm

## Команды

```bash
npm run generate
npm run verify
npm test
node scripts/check-comment-hygiene.mjs --repo <name>
node scripts/check-comment-hygiene.mjs --check --repo <name>
```

## Границы

Открытая структура проекта:

```text
project/
  queryn.json
  notes/
  assets/
  artifacts/
  sessions/
  relations/
  .queryn/
```

`schemas/` содержит публичные JSON Schema проекта, артефактов, sessions, jobs, context и extension manifest. `protocol/` фиксирует Queryn Tool Protocol v1 и локальный RPC. Примеры находятся в `examples/`.

Проект остаётся понятным после удаления `.queryn/`. Отсутствующее расширение, модель, AI или OCI не препятствуют открытию.

`npm run generate` генерирует контрактные TypeScript-типы из схем в
`queryn-core/packages/types/src/generated/` и `queryn-sdk/src/generated/`.
Сгенерированные файлы коммитятся, ручное редактирование запрещено: изменение
контракта вносится в схему, затем типы перегенерируются.

`npm run verify` проверяет локальные `$ref` во всех схемах и валидность golden
Reborn project. Оба репозитория-потребителя запускают эту же проверку свежести
перед своими тестами через `pretest`. В multi-repo checkout пути можно передать
через `--core` и `--sdk`, а режим `--check` падает, если сгенерированные файлы
устарели относительно схем.

`npm test` запускает тесты сканера гигиены комментариев. Для миграционного аудита
используйте `node scripts/check-comment-hygiene.mjs --repo <name>` в режиме отчета
или добавьте `--check`, чтобы завершить команду с ошибкой при нарушении. Пути и
правила `TODO` для репозиториев находятся в `scripts/comment-hygiene/repos.json`.

Контрактные векторы `slugify` и `slugifyIdentifier` хранятся в
`contract/slug-vectors.json`. Core и desktop проверяют их одним набором данных,
чтобы зеркало функции в renderer не расходилось с доменной реализацией.

- Репозиторий владеет folder-based форматом проекта, JSON Schema, протоколами и
  проверяемыми примерами.
- Стабильные машинные контракты сначала меняются здесь, затем типы
  перегенерируются для потребителей.
- Реализация операций с проектом находится в `queryn-core`, desktop и runtime
  потребляют эти контракты через свои API.
- Папка проекта остаётся источником истины. `.queryn/` содержит производное
  состояние и может быть пересобрана без потери понятности проекта.

## Связанные репозитории

- `queryn-docs` описывает продуктовую и архитектурную позицию.
- `queryn-core` реализует общие TypeScript-пакеты по этим контрактам.
- `queryn-desktop` читает и записывает формат проекта через core API.
- `queryn-runtime` использует формат для проектов, сессий, артефактов и jobs.
- `queryn-sdk` публикует контракт Extension Manifest v1.
- `queryn-extensions` содержит проверяемые примеры расширений и каталог.
