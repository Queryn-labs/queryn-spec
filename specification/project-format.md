# Формат проекта Queryn

Проект Queryn - директория на диске. Эта директория является редактируемым источником истины.

## Формат 0.2

```text
project/
  queryn.json
  notes/
  assets/
  artifacts/
  sessions/
  relations/
  .queryn/
```

### `queryn.json`

Manifest проекта. Он идентифицирует проект, объявляет версию формата и хранит метаданные уровня проекта.

### `notes/`

Markdown-конспекты. Конспект может содержать YAML frontmatter. Обычный Markdown без frontmatter остается допустимым содержимым.

`notes/` может содержать вложенные папки. Вложенные папки являются частью пользовательской структуры проекта и должны оставаться обычными директориями.

### `assets/`

Пользовательские файлы, на которые ссылаются конспекты, карточки или другие данные проекта.

`assets/` может содержать вложенные папки. Файлы остаются обычными файлами на диске; приложение не должно требовать отдельной базы данных для их просмотра или переноса.

### `.queryn/`

Application metadata, кеши, индексы и производное состояние. Проект должен оставаться понятным, если эта директория удалена и пересобрана.

### `artifacts/`

JSON descriptors типизированных результатов и `data/` для payloads, которым не
подходит `notes/` или `assets/`. Descriptor ссылается только на project-relative
paths, хранит SHA-256 и provenance. Обычная заметка или файл получает descriptor
только тогда, когда operation flow явно регистрирует или публикует его результат.
Нативное редактирование notes и assets не создаёт descriptor автоматически.

### `sessions/`

Переносимые рабочие сессии. Каждая сессия хранит `session.json` и append-only
`events.jsonl`. Текущий runtime записывает видимые сообщения, вызовы tool и
operation, observations, approvals, результаты и ссылки на артефакты. Отдельный
структурный `AgentPlan` текущий агентный контракт не создаёт. Событие `plan`,
сохранившееся в ранней схеме событий, не означает наличие pipeline или
поддержки RPC-планирования. Hidden model reasoning не сохраняется.

### `relations/`

Связи между артефактами. Relation type может быть встроенным или namespaced типом
расширения.

## Формат 0.1

Проекты 0.1 остаются читаемыми:

```text
project/
  queryn.json
  notes/
  assets/
  cards/
  graph/
  ai/
  .queryn/
```

Миграция в 0.2 является явной операцией с dry-run и backup manifest. Это план
изменения формата проекта, а не агентный план выполнения. Открытие проекта не
должно молча менять его формат.

### `cards/`

Структурированные учебные карточки в виде JSON-файлов.

### `graph/`

Связи между конспектами, карточками, файлами и другими сущностями проекта.

### `ai/`

AI-связанные артефакты, которые пользователь явно сохраняет в проект. Runtime caches должны оставаться в `.queryn/`.

В 0.2 новые AI-результаты используют общую модель `artifacts/`; существующая
директория `ai/` сохраняется для совместимости.

## Подключенные расширения

`queryn.json.extensions` содержит только переносимые требования `{ id, version,
enabled }`. Поле `version` принимает точную SemVer-версию либо поддерживаемый
range (`^`, `~`, `*`, `latest`). Выбранная из установленных side-by-side версий
и integrity пакета записываются в удаляемый
`.queryn/extensions/lock.json`; этот lock не является переносимым требованием и
может быть пересобран.

Secrets, выданные permissions и сохранённые policy rules не должны приниматься
из файлов проекта: это локальное доверие runtime. При переносе пользователь
выдаёт permissions заново. Аудит самих решений остаётся в session events. При
отсутствии расширения проект открывается, а связанная возможность получает
состояние `missing`.

## Атомарная публикация

Сторонний runtime не пишет в проект напрямую. Он возвращает candidate outputs в
изолированный outbox. Host проверяет paths, symlinks, размеры, MIME, schema и
hash, после чего атомарно переносит payload и создает descriptor. Частичный output
не является артефактом проекта.

## Ссылки MVP

Markdown-конспекты могут ссылаться друг на друга через wiki-links:

```text
[[Название статьи]]
[[папка/название-статьи|Понятный текст]]
```

Markdown-конспекты могут ссылаться на вложения через обычные Markdown-ссылки на project-relative путь:

```text
[diagram](assets/diagram.png)
[archive](assets/source/source.zip)
```

Эти соглашения не расширяют `queryn.json`. Они описывают совместимый рабочий слой поверх обычного Markdown и обычных файлов проекта.

## Архивный транспорт

Будущий формат `.osnp` - архивный транспорт для папки проекта. Он должен сохранять структуру папки и manifest. Он не является основным форматом редактирования.
